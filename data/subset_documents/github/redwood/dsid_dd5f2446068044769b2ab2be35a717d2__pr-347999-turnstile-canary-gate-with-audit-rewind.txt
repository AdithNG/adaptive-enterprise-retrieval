Turnstile canary gating with audit-rewind and session-fence support

Motivation: We need a safer canary primitive that enforces session-coherent promotion and provides a forensic-backed automated rollback that can optionally rewind recent traffic for replay testing. The Turnstile gate implements a session-fence: during promotion the controller guarantees that sessions routed to the candidate model are isolated and can be rewound (replayed) against the golden variant for postmortem verification. The audit-rewind helper materializes compact, indexed per-cohort artifacts that let SREs and devs replay a timebox of requests deterministically.

What this PR does: implements a new rollout gate (turnstile), a compact on-disk audit store format, controller logic to fence sessions during canaries, a replay CLI for investigators, and operator docs/playbooks. Key behaviors: session affinity maintained while candidate is in the fenced lane; if the gate trips (latency/regression thresholds) the controller can trigger an automated rollback and optionally kick off an audit-rewind job to capture and replay affected sessions for debugging. The rewind job supports partial replays (sampling by cohort, developer tags, or explicit request IDs).

Testing notes: initial CI run flagged a flaky test in the sampling path (tests/turnstile_integration_test.py) due to timing assumptions; increased test harness timeouts and introduced deterministic pseudorandom seeds for sampling. Local integration: ran a 1k qps synthetic canary against the staging cluster with session stickiness and verified that scoreboard metrics (turnstile.active_sessions, turnstile.replay_candidates, turnstile.rollback_triggers) are emitted. Replayed a 5-minute window with replay_cli and confirmed parity for 98% of traced response hashes.

Backward compatibility and safety: the Turnstile gate plugs in as an optional gate in existing rollout policy YAMLs; if not referenced, there is zero behavioral change. The audit store expires by default after 72 hours and is configurable per-tenant to avoid storage blowup. The rewind path is read-only with a configurable dry-run mode so it can be used without automatically shadowing production traffic.

Operational concerns: 
- Storage: audit artifacts are compact (indexed delta blobs) but operators should monitor telemetry.audit_store_bytes; default retention is conservative. 
- Privacy: audit artifacts contain request metadata and user-cohort tags (no PII allowed). We added sanitization hooks in telemetry/audit_store.go and a KMS flag for encrypting on write. 

Related work: builds on ENG-1072 (session-anchored shadow bridge) and complements ENG-1624 (telemetry replay framework). This PR also references SUP-783 for a customer incident that motivated faster forensic replays.

How to review: focus on the controller invariants in turnstile_controller.go and tests/turnstile_unit_test.py. Replay CLI is small and intentionally opinionated — review for safety knobs. docs/runbooks/turnstile.md contains operator playbook and run examples.

Notes for release: enable behind feature flag rollout.turnstile_enabled=false by default for 2 weeks, then roll to opt-in tenants.
