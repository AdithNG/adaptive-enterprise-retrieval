Lightweight lint harness, dep-rotation tool, and staged release-hook refactor

Context: Our existing lint pipeline is heavy (Docker-based linters and full repo checks on every PR) which slows feedback and increases CI cost. Release hooks were tightly coupled to the monolithic workflow, making staged releases fragile when we split artifacts. This PR introduces three coordinated changes: 1) a lightweight lint harness (fastpath) that runs staged checks locally and in CI for touched files only; 2) a dep-rotation tool that automates safe, staged upgrades/removals of transitive dependencies; 3) a refactor of release hooks into a two-stage flow (prepare + smoke) to improve reliability and enable canary releases.

What changed (high level): implemented a new fast lint harness written in TypeScript that caches parsed ASTs and computes minimal lint sets for PR diffs; replaced a number of heavyweight Docker lint invocations in CI with node-run fastpaths and fallbacks to the legacy image for full scans on demand; added tools/dep-rotation (small Go binary + orchestration script) that iterates through candidate transitive deps, generates rotation PRs with lightweight test matrices, and annotates each candidate with rollout status; refactored workflows/.github/workflows/release.yml into prepare-release.yml and release-smoke.yml and added a new staged-release label that gates automated canaries; added a simple preflight compatibility check that runs a pinned set of integration samplers against the candidate build before promoting artifacts.

Motivation: reduce PR feedback time by ~3x for typical code changes, reduce CI spend on lints for high-volume PRs, and make dependency churn safer by automating gradual rollouts and rollbacks. Separating release steps reduces failed release rollouts and makes the failure modes more observable and recoverable.

How to exercise locally:
- Run the fast lint harness: ./scripts/lint-fast --staged
- Create a trial rotation: ./tools/dep-rotation/rotate --dry-run --candidate lodash@4.18.0
- Trigger staged release locally with: gh workflow run prepare-release.yml --ref feature/branch

Risks and mitigations:
- Risk: fastpath lint may miss some cross-file lint rules. Mitigation: CI still runs full scan on main branch and the fallback job runs full lints on PRs touching build/infra.
- Risk: dep-rotation may generate many noisy PRs. Mitigation: tool defaults to dry-run and has an auto-throttle; rotation PRs are created under tools/automation and labelled rotateme.
