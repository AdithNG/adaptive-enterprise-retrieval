align-telemetry-schema-preserve-stream-cursors-and-soft-retry-profiles-across-py-ts-go

Motivation: SDKs had subtle divergences in telemetry keys and streaming reconnect behaviour that make cross-language observability and incident triage harder. In particular: (1) telemetry field names and types were inconsistent across Python/TypeScript/Go, (2) streaming clients in TS/Go could drop/lose a cursor when a reconnect happened during a partial frame, and (3) retry defaults were aggressive for short-lived network blips and caused short-lived request storms. This PR synchronizes a compact telemetry schema, preserves stream cursor state across reconnects, and relaxes retry presets to 'soft' profiles across all three SDKs.

Design summary:
- Introduce a canonical telemetry envelope (telemetry.v=1 -> telemetry.schema=redwood_sdk_v1) and add typed fields: request_id, sdk.name, sdk.version, route.hash, client.sequence_hint. Old keys are mapped in a one-time shim for backwards compatibility.
- Streaming: add a small resume protocol that atomically persists the last completed frame id and pending buffer during reconnect; implement idempotent resume handshake in TS and Go streaming clients, and ensure Python client exposes the same resume token.
- Retries: change default retry/secondary backoff parameters to be less aggressive (lower attempt multiplier, wider jitter window, short circuit on HTTP 429->respect Retry-After).

Migration & compatibility: The telemetry shim maps legacy keys (trace_id -> telemetry.request_id, SDK -> sdk.name) for one release cycle; no customer-facing breaking changes expected. Streaming resume uses a resume_token that is sent by the client on reconnect; servers that don't understand it fall back to full restart, so behavior is graceful.
