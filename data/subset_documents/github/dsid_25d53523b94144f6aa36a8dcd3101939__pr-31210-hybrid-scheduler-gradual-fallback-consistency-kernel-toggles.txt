hybrid-scheduler-gradual-fallback-consistency-kernel-toggles

Summary: Introduces a hybrid scheduling path that allows requests to start on the fast, lower-precision kernel chain and transparently fall back to a conservative (safe-mode) kernel when numerical consistency checks fail or when upstream correctness policies are triggered. This change targets tail-latency and cost while preserving correctness guarantees for production workloads.
Motivation and context: We've seen intermittent regression cases where aggressive fast-path kernels (quantized/mixed-precision attention) provide large median improvements but occasionally diverge on corner conditions for long sequences or very large batch re-ordering. Existing fastpath gating is binary and heavily conservative, causing either too many misses (performance lost) or too few (correctness risk). This PR implements a gradual fallback strategy, per-request precision toggles, and a non-blocking correctness validator that reduces unnecessary escalations.
What changed (high level):
- New hybrid_scheduler module that tracks per-request health and assigns a decay score; requests with low confidence are staged onto safe-mode without global blocking.
- Introduced "precision_toggles": a lightweight per-layer hint metadata carried on requests so we can switch specific kernels from int8->fp16 or fp16->fp32 at layer granularity.
- Added an asynchronous correctness validator that performs lightweight checksum/consistency probes on a sampled subset of tokens; violations trigger targeted fallbacks rather than global disable.
- KV cache eviction integration: cache_manager now exposes a fast eviction hint for requests on fallback to reduce memory pressure and avoid cache thrash during degen sequences.
- Continuous batcher: added an adaptive window that short-circuits batching for requests flagged with high fallback probability to maintain tail latency.
- New unit and perf tests plus a small demo notebook exercising progressive fallback and toggles.
Performance notes: On our TPU and A100 perf lab runs with llama-variant workloads (seq=1024, mix of short/long prompts):
- Median latency (P50) improved by ~9% across the board due to opportunistic fast-path use.
- P95 improvements vary: up to 12% for conversation loads with moderate concurrency.
- P99 improved by 6-8% in scenarios where adaptive batching prevented harmful queueing.
- Cost: token compute cost reduced by ~7% in synthetic traces with 70% of requests eligible for fast-path.
Correctness/regression mitigation:
- The async validator samples ~1% of requests by default; when a mismatch is seen it records a fingerprint and triggers targeted re-execution on fp32 for that request only.
- Added metrics and tracing (fallback.reason, fallback.scope, fallback.count) to Redwood Console to make any degradation visible immediately.
Backwards compatibility and rollout:
- Feature gated behind config runtime.hybrid_fallback.enabled (off by default).
- Safe default: the scheduler starts in observation mode where it logs but does not alter routes; opt-in rollout via Dedicated flags and console toggles.
