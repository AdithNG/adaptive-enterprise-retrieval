Hosted API per-token experiment: asymmetric input/output rates, streaming surcharge, and monthly minimums

Background:
Redwood's hosted API pricing currently charges a single combined per-token rate. Customers and internal commercial teams have raised concerns: (1) input tokens are cost-inefficient to charge at parity with output tokens for streaming use cases; (2) streaming sessions produce high output variance leading to unpredictable bills; (3) enterprise customers prefer a contract-level monthly minimum to stabilize spend and commit capacity.

Goal:
Run a controlled set of experiments to evaluate revenue, usage, and product impact for three levers: asymmetric input/output token rates (e.g., input 0.6x of output), a per-session streaming surcharge (flat per-stream fee), and optional monthly minimum tiers for enterprise contracts. Determine optimal defaults for hosted API that balance competitiveness, predictability, and unit economics.

Success metrics (primary):
- Net revenue delta vs baseline (30d and 90d) as % and absolute dollars
- Average revenue per active customer (ARPC) change
- Usage shift: tokens generated per session and sessions per customer
- Churn/upgrade signal among high-volume customers
- Model-serving cost ratio (cost-to-revenue) per-metric bucket

Success metrics (secondary):
- Developer feedback / NPS from trial cohorts
- Support ticket volume related to billing and streaming behavior
- Contract negotiation speed for enterprise pilots

Experiment design:
Cohorts (A/B/C):
- Control (A): existing single per-token pricing (baseline)
- Variant B (asymmetric tokens): input tokens priced at 60% of output tokens; output unchanged. No minimums, no streaming surcharge.
- Variant C (streaming + min): asymmetric tokens at 70% input rate + streaming surcharge of $0.003 per stream (applies when Response-Stream header used) + optional monthly minimum tier options surfaced to accounts > $2k MRR via console offer.

Allocation and duration:
- Randomized assignment for new sign-ups and a subset of existing self-serve accounts (opt-out eligible) for 60 days; evaluate after 30 and 60 days.
- Enterprise customers excluded by default unless flagged for sales-assisted pilot (handled via PM sales ops).

Instrumentation & data collection requirements (ENG dependencies):
- Billing pipeline: tag tokens as "input" vs "output" in billing events (ENG-2892).
- Streaming detection: count per-session streaming starts via the streaming endpoint telemetry and expose a per-stream metric in billing events.
- Cohort flags: ensure feature flagging per-account and link to console UI variation (PM-4500).
- Cost model update: runtime team to provide token-level cost estimate (amortized GPU cost per input vs output tokens) for each model family.

Rollout plan & gating:
- Phase 0 (internal): bench the billing changes in sandbox, confirm cost reconciliation for first 1M tokens.
- Phase 1 (beta): enable cohorts B & C for 15% of new self-serve signups and 10 selected medium accounts (sales-approved). Monitor for billing anomalies, support volume, and revenue signals.
- Phase 2 (evaluate): full 60-day run; present findings to Pricing Council with recommended default.
- Gate: rollback on any >5% spike in billing disputes or >10% increase in usage without matching revenue (risking negative unit economics).

Enterprise contract & security questionnaire implications:
- Monthly minimums need contract language for billing proration, overage handling, and termination commitments. Legal to prepare a template addendum for minimum tiers.
- Security questionnaire updates required: clarify that pricing tiers do not change data handling or retention policies; add Q/A explaining streaming surcharge and how streaming telemetry is collected (no PII captured for billing).
- For enterprise pilots, we must ensure KMS/HSM billing visibility and that quantization/compaction techniques used for cost savings do not affect contractual data isolation requirements.

Risks & mitigations:
- Customer confusion: create clear console UX language and in-bill line items (separate input/output rows and streaming surcharge line). Run micro-copy A/B tests.
- Competitive positioning: monitor competitor price changes; prepare an opt-in promotional credit for high-sensitivity customers.
- Revenue regression: use minimum-tier pilot to provide downside protection for large accounts.
