Interleaved Tool Invoker: Recursion Throttle & Structured Result Contracts

Implement a robust invoker for multi-tool chains that interleaves streaming token emission with synchronous/asynchronous tool calls while preventing runaway recursion/loops and maintaining a structured-result contract for backwards compatibility. This ticket covers runtime enforcement (throttles, depth limits, loop detection), a compatibility shim for older SDKs that expect inlined result injection, formal structured-output schemas for tool responses, and telemetry to monitor chain health. Goal: allow callers to stream partial tokens to clients during long-running tool calls without losing safety guarantees or introducing breaking changes for existing clients.
Invoker enforces a default maximum chain depth of 5 and provides per-request override up to 20 with admin flag
Loop detection triggers a deterministic abort with a structured error payload (error.code and error.details) and emits a telemetry event
Streaming tokens continue to flow to the client while a tool call is running; client sees 'tool.invocation.start' and 'tool.invocation.end' structured events in the stream
Compatibility shim automatically converts older 'inline_result' tool formats to new structured-result schema for SDKs v<=2.4 without changing server-side tool implementations
End-to-end tests that simulate recursive tool chains (depth, cycles, long-running tools) pass in CI and on Dedicated infra
Metrics exist: chain_depth histogram, loop_detection_count, per-request tool_call_count, streaming-latency impact heatmap
Documentation (API reference + migration guide) published under docs/tool-invoker and linked in PR
