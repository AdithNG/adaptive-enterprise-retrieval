Quick context: Northgrove Health (regional hospital chain, ~12 sites) — want LLM-powered triage assistant to summarize ED nurse intake, suggest next steps to clinicians, and generate discharge instructions drafts. Must be PHI-safe and deployable inside their VPC (no cross-tenant data plane). Call 11/12 recap below (notes to self, messy).

Call summary (high level):
- Goal: replace / augment manual note summarization and care-path suggestions; not decision automation, clinicians must sign off.
- Primary constraint: all PHI MUST remain in customer network; they have an existing AWS VPC + transit gateway.
- SLA ask: interactive latency target ~ <200ms p50 for short summaries (200-600 token outputs). Peak concurrencies unknown but expect bursts during shift change (estimate 3–6 concurrent writers per site).
- Data residency: US-only, logs/audits must be exported to their Splunk; minimal telemetry to Redwood (token counts, errors) only if permitted by contract.

Raw technical notes / gotchas: (unpolished)
- EHR notes are VERY long and noisy (copied templates, macros). Token explosion risk — need aggressive input truncation + prefix filtering at the agent layer.
- RAG approach required for up-to-date med protocols (we cannot store EHR in hosted Redwood). Suggest: vector DB inside their VPC + local document chunker + private retrieval service.
- KMS: they insist on customer-managed KMS for model keys and any encryption at rest. Need to confirm Redwood Private KMS integration (HSM/KMS options).
- Network: outbound connections from private inference nodes must be blocked; control plane communication over a customer-approved management endpoint (their firewall rules will be strict).
- Model choice: they asked about using an LLM with reduced hallucination for clinical text. We should propose a medically-tuned open model + evals; consider Redwood Optimize recommendations (quantized 8-bit to fit GPUs).
- Streaming: clinicians want near real-time typing/streaming of summary — confirm that Private deployment supports token streaming over websocket within VPC.
- Audit logs: must include per-request redaction summary (which fields were removed) and hashes for content provenance. Also retention policy (90 days accessible, archived 7 years) — legal asked.
- Cost sensitivity: hospital IT flagged budget — reserved nodes vs burst capacity discussion. Offer hybrid: dedicated baseline + burst to hosted (but hosted blocked by PHI). So likely need capacity plan for Dedicated inside customer infra or bare-metal in their data center.

Operational considerations:
- Monitoring: they want per-route latency + token-level cost breakdown forwarded to their Splunk. Need a small collector agent or S3 export.
- Rollouts: canary traffic must be controllable per-site. They requested ability to pin model versions per hospital for phased rollout.
- Fallback: if model unavailable, fallback to a constrained template-based summarizer (local rules) to avoid outages.
