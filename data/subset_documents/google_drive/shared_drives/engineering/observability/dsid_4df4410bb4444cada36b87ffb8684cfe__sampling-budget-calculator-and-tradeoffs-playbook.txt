Operational Sampling Budget Calculator and Tradeoffs Playbook

Summary:
This playbook provides a practical, operator-facing calculator and decision guide for allocating a global sampling budget across traces and metrics for LLM inference services. The goal is to hold investigation utility high while keeping telemetry query and storage cost within predictable bounds. This doc combines definitions, quick formulas, worked examples, dashboard query suggestions, trace annotation conventions, and an implementation checklist for rollout.

Why we need an explicit sampling budget:
- Observability cost is dominated by trace ingestion and high-cardinality spans when tokenized inference spikes.
- Unbounded trace retention or aggressive sampling can run up query costs and storage; conversely, naive sampling may lose fidelity for regression hunts.
- A transparent sampling budget aligns product, SRE, and finance tradeoffs and supports automated enforcement (rate-limited trace-ingest proxies).

Definitions and constraints:
- Sampling budget (SB): the total number of full traces (or trace-equivalent units) we allow to be stored/queried per day for a given service or tenant.
- Trace-equivalent unit (TEU): normalized unit to combine full traces and span-samples. Example: TEU = 1 full trace (all spans) = 10 partial-span samples (heuristic).
- Baseline telemetry needs: alerts, SLOs, canaries use synthetic traces outside SB (covered by probe quota).
- Cost cap: daily dollars allocated for observability for this service.

Core formulas (operator cheat-sheet):
- SB = floor(CostCap / CostPerTEU)
  - CostPerTEU = (AvgTraceSizeBytes * StorageCostPerByte + QueryCostPerTrace) / compression_factor
- SampleRateNeeded = min(1.0, SB / EstimatedDailyTrafficTraces)
- Multi-tier retention: FastTier (7d, high-quantile) consumes f_fast fraction of SB, WarmTier (30d) consumes f_warm, ColdTier archived.

Worked example (numbers are illustrative):
- Assumptions: EstimatedDailyTrafficTraces = 1,200,000 user traces; AvgTraceSizeBytes = 25KB; StorageCostPerByte = $0.0000005/day (platform rate); QueryCostPerTrace = $0.00001 average; compression_factor = 4 (native compression + rollups).
- CostPerTEU = (25,000 * 0.0000005 + 0.00001) / 4 = (0.0125 + 0.00001)/4 ≈ 0.00313/4? (note: keep units consistent) -> simplified: CostPerTEU ≈ $0.0032
- If CostCap = $250/day -> SB ≈ 78,125 TEUs/day
- SampleRateNeeded = 78,125 / 1,200,000 ≈ 6.5% sample rate
- Tiering: FastTier f_fast = 0.25 -> 19,531 TEUs/day routed to 7d retention for spike investigations; WarmTier f_warm = 0.75 -> remainder to 30d aggregated storage.

Practical knobs and patterns:
1) Severity-weighted sampling: always sample 100% for ERROR/500 statuses, 25% for WARN, and target rate for OK. This keeps signal for incidents.
2) Session-provenance priority: sample requests with cold-kv-cache or model-fallback flags at higher rates. Add tags: kv_cache_warmth=0/1, fallback=true.
3) Prefix- and route-aware hashing: keep head-of-session traces (first 1–2 requests) at higher rate to capture priming latency.
4) Adaptive burst allocation: when latency SLOs degrade, temporarily boost FastTier allocation (circuit-breaker with auto-reversion).
5) Synthetic probes excluded: synthetic canaries and perf probes are allocated a separate probe budget.

Trace annotation canonical keys (operator standard):
- trace.owner_service: string (e.g., "model-router")
- trace.tenant_id: tenant or customer id (hashed)
- trace.request_type: {sync, async, batch, embedding}
- trace.kv_cache.hit: {true,false}
- trace.kv_cache.warmth: {hot,warm,cold}
- trace.model.id: model identifier + quantization tag
- trace.model.variant: {fp16,4bit,8bit}
- trace.fallback.reason: short code (e.g., QUOTA_EXCEEDED, OOM, NETWORK)
- trace.latency.tokens_gen_ms: integer
- trace.prompt_hash: token-level prompt fingerprint (scrubbed/hashed)

Metric and dashboard guidance (compact operator notes):
- Lightweight dashboards should expose: SLO p99 latency, per-tenant sample-rate, TEU burn-rate, FastTier headroom, KV-cache-warmth distribution, model-fallback-rate by route.
- Example PromQL-ish query placeholders: total_teu_burn_rate_rate = sum(rate(telemetry_teu_ingest_total[5m])) by (service)
- FastTier headroom panel: headroom = SB_fast - current_fast_teu_burn; alert when headroom < 15% for 10m.
- Cost forecast panel: rolling30d_cost = sum_over_days( daily_teu * CostPerTEU ) with projection for next 7d (linear fit of recent 14d slope).

Operator runbook snippets (when burn spikes):
- If TEU burn spikes > 2x baseline for 30m: 1) Check if rollout flag active (link to PR), 2) throttle non-critical tenants (predefined list), 3) increase sampling granularity (drop some span tags to reduce AvgTraceSize), 4) flip adaptive-burst policy to limit FastTier uplift.
- If p99 latency increases and TEU burn stable: investigate model routing changes, look for model.variant churn in traces.

Implementation checklist for rollout (minimal viable guardrails):
- [ ] Add trace annotation keys to model-router and request-proxy (see keys above).
- [ ] Implement TEU meter in ingest proxy (counts traces and partial-span samples into TEU equivalents).
- [ ] Expose SB and current burn as metrics: telemetry.teu_budget_total, telemetry.teu_burn_rate.
- [ ] Dashboard panels: TEU burn, sample rate by tenant, headroom alerts, cost forecast.
- [ ] Simple enforcement controller: when burn > 95% of SB, reduce non-critical tenant sample rate by factor 2 and send Slack notification to #ops.
- [ ] Postmortem template for sampling budget overruns (include telemetry cut and root cause).

Open questions and tradeoffs (for leadership review):
- TEU normalization heuristics are heuristic-heavy; do we standardize on trace-size percentile bucketing instead?
- Should we charge tenants for TEU usage (internal piggybacking) or keep as platform cost under a shared observability pool?
- Compression and indexing improvements can change CostPerTEU; we need a quarterly recalibration job.

Appendix: quick calculator steps for on-call use:
1) Look up CostCap (dollars/day) in the budget sheet.
2) Read current AvgTraceSize (daily avg) from telemetry.size.avg metric.
3) Compute CostPerTEU using platform rates from infra-finance doc.
4) Derive SB and translate to sample rate via SampleRateNeeded formula.
5) If immediate enforcement needed, use the enforcement controller to scale down non-critical samples by factor ceil(current_burn / SB).
