SSE multipath handoff causes out-of-order heartbeat and incomplete terminal epilogue

Issue summary: Customer reports SSE sessions truncate final paragraph and lose trailing metadata when the client experiences a multipath network handoff (e.g., WiFi -> cellular) during an in-flight stream. Impact: several API calls from Nimbus Health observing truncated clinical notes at the end of streams, causing downstream data loss and retransmission. Environment: prod (us-east), dedicated enterprise tenant. Observed behavior: when the TCP path migrates and the edge layer rebinds the session, heartbeat frames are occasionally delivered out-of-order relative to payload fragments; the SDK resumes but the final 'end' marker and trailing metadata are missing or delayed past client timeout. Expected behavior: heartbeat frames should be ordering-neutral for stream framing; resume should replay missing payloads or ensure terminal events are reliably delivered after a handoff. Customer impact: moderate — several generation completions dropped (missing 1-2 sentences) affecting clinical note integrity.
1) Use the customer's SDK to open an SSE streaming request against redwood-chat-13b in us-east with verbose keepalive (200ms).
2) Start a long completion (~800 tokens) that will stream for >10s, include trailing JSON metadata in the final chunk,
3) Mid-stream, trigger network path migration on client (simulate WiFi->cellular using multipath proxy or local NAT path change).
4) Observe client reconnect/resume behavior and whether final 'end' event and metadata arrive or are truncated.
5) Repeat behind an enterprise transparent proxy / TLS-inspecting middlebox to reproduce edge-proxy interaction.
