Tenant cookie-domain leakage during canary causes cross-tenant session bounce and unpin/fallback routing

Issue summary:
During a weighted canary of a header normalization change to edge-proxy, the Set-Cookie Domain was normalized to a parent zone instead of tenant scope for some requests. This caused tenant-scoped sticky cookies to be reused across tenant subdomains, producing session affinity flips, model unpinning, and routing fallbacks to legacy variants.

Impact:
- ClarionDocs (enterprise) reported mixed outputs and quality regressions for production streams between 2026-03-12 09:15 and ongoing.
- A subset of their sessions were re-routed from their pinned model (gpt-neoxt-20B) to an older variant, causing unacceptable answer drift.
- Affects prod/us-east dedicated pool for this tenant; customer-facing SLAs at risk.

Environment:
- prod/us-east, ClarionDocs dedicated tenancy, requests pass through edge-proxy cluster ep-us1-edge-a/b, session cookies stored in redis-session-store-us1, serving-runtime handling pinned model on dedicated GPU pool.

1) Use curl to emulate ClarionDocs host header and initiate session:
   curl -v -H 'Host: app.clariondocs.com' -H 'Authorization: Bearer <token>' https://api.redwood.ai/v1/chat
2) Observe Set-Cookie header returned by edge-proxy (should be Domain=app.clariondocs.com but affected responses show Domain=.clariondocs.com or Domain=.redwood.ai)
3) Use same cookie from one subdomain request on a different subdomain/tenant-like host header and observe session is accepted and routed to a different model variant.
4) Replay workload via traffic-mirror to compare routing decisions between edge with old vs new header normalization.

Timeline:
- 2026-03-12 08:50: Canary started for PR 4123 (edge-proxy) which contained a normalization routine that canonicalizes Host->Domain for Set-Cookie.
- 09:15: Customer support alerts started to come in reporting inconsistent generations.
- 09:30: Sampling showed ~0.8% of ClarionDocs sessions had cookies with Domain set to parent zone ('.clariondocs.com') instead of exact host.
- 10:00: Routing logs show affinity check uses cookie domain to scope tenant pins; parent-domain cookies cause cross-subdomain reuse leading to pin unbind and fallback selection.
Hypothesis:
- The normalization change treats hostnames with multiple labels as public suffix-inspected and incorrectly maps tenant hostnames to parent zones when a tenant uses a custom domain pattern. Edge code used a heuristics list that misclassified clariondocs's custom domain.
Evidence:
- PR 4123 diff includes function cookie_util::derive_cookie_domain(host) with updated heuristics.
- Replaying requests against older edge-proxy binary reproduces correct Domain values and preserves pinning.
