Connection-affinity flip causes half-closed SSE stream and partial JSON choice payload

Issue summary: Customer sees truncated JSON choice objects and a half-closed SSE stream after an apparent connection affinity flip at the edge. Impact: Generated chat responses end mid-choice and client receives a JSON fragment without a terminating 'end' event, causing parser errors and dropped messages for the user. Environment: Production, us-east, Slateware Analytics enterprise account using SSE streaming via the public Redwood API behind a third-party CDN/proxy.

Observed behavior:
- Long-running SSE stream will intermittently stop sending the terminal 'end' event while the payload ends mid-JSON object (e.g., truncated choices).
- Clients report JSON parse errors or stuck UI waiting for end-of-stream.
- Issue correlates with a short window where the connection is handed between two edge proxies (affinity flip).

Expected behavior:
- Streaming sessions should preserve choice boundaries across proxy/edge changes and always deliver a final end-of-stream marker or a resume token so clients can reconcile partial payloads.

Steps to reproduce (attempted):
1) Use Slateware's SSE client connected to prod-us-east endpoint.
2) Start a multi-turn chat that streams a long completion (>10k tokens).
3) Simulate upstream affinity change via controlled proxy failover (performed in staging) or wait for natural brief edge handoff.
4) Observe the SSE stream for missing terminal event or truncated JSON choice.

Logs & artifacts:
- Excerpt from edge proxy logs: "AffinityFlip: active->standby 10:33:41Z session=abc123 remote=10.2.5.8"
- Serving runtime tail: "stream_writer: write_partial_chunk: connection half-closed while flushing kvcache"
- Client-side console: "SyntaxError: Unexpected end of JSON input at parse (client-stream-parser.js:214)"
- Session trace IDs: ["trace-us-east-20260312-7a1f", "trace-us-east-20260312-7a2b"]

Immediate impact: A small number of enterprise customers experience failed chat sessions leading to retries and elevated support volume. Slateware reported ~7 failures in the last 24 hours, each during bursts of concurrent long-stream requests.

Reproduced in a controlled staging handoff: we were able to trigger the half-closed behavior when the edge proxy reconnected a session to a different backend instance without completing the stream drain.
Hypothesis 1: Connection affinity flip leads to early FIN from upstream proxy while runtime still flushes trailing chunk, causing truncated last chunk to be dropped by new connection.
Hypothesis 2: Edge proxy performs a TCP-level reconnect that collapses buffered chunk boundaries; our SSE framing relies on exact chunk boundaries for finalizer metadata and does not tolerate partial reassembly.
We verified that the serving runtime emits a final 'end' delimiter in normal flows; missing delimiter correlates to observed affinity handoff window in edge logs.
Captured pcap across service mesh shows half-close (FIN) from old proxy followed by immediate reset path, confirming race between flush and reattach.
No evidence of model-level termination: model logs show generation completed and tokens pushed to runtime output buffer prior to flush failure.
Customer-side SDK currently treats any parse error as non-recoverable; suggested SDK change to tolerate partial JSON and request a resume token from server (longer-term).
