Alex / team —

Below is an operational summary to make the commitments concrete. Attaching the current subprocessor inventory for your review.

Runtime enforcement (no-training + telemetry opt-out):
- Tenant flag: We have a per-tenant runtime flag "no_model_learning" instantiated at request ingress. When set, the request path bypasses any learning/experimentation endpoints and writes only into ephemeral caches with a TTL of 1 hour (configurable by agreement).
- KV cache & prefix caching: For latency-sensitive workloads we still use ephemeral KV caches; these are not persisted to training pipelines.
- Telemetry: We separate telemetry into billing metrics (aggregated token counts) and telemetry-flags for health/debug. Opt-out removes tenant-id from all non-billing telemetry streams and writes anonymized buckets to a separate retention pipeline.
- Audit & deletion flow: Deletion request triggers: (1) mark items as deleted (index), (2) purge ephemeral caches and permanent logs within 24 hours, (3) generate exportable audit bundle (jsonL events) including request ids and timestamps. We retain a signed attestation for 12 months by default.

Subprocessors & residency: See attached subprocessor_inventory.csv — columns: name, role, region, access_level. We are able to provide onshore-only routing for traffic (us-east, us-west) and to constrain data plane so only onshore subprocessors handle plaintext when requested.

Latency/throughput considerations: Enforcing no-learning and telemetry opt-out has negligible steady-state latency (<5 ms p50 impact) but may affect our ability to use low-cost experimental batching for some multi-tenant pools. For guaranteed throughput & subprocessor isolation we recommend Dedicated capacity (reserved GPU pools) for Medicore's production traffic.
