Quick answers:
- Retention: Hosted defaults to 90 days (customer-configurable to 365 days on paid tiers); Dedicated can be configured to 7 years via reserved contracts; Private (VPC/on-prem) retention is customer-controlled and can meet regulatory windows (we commonly support 7 years+).
- Export formats: Exports are newline-delimited JSON (NDJSON) or Parquet; we support delivery to customer-controlled S3 buckets (S3 API + SSE-KMS), direct API pulls (paginated), and time-windowed exports via the Console or API. Exports are checksummed and optionally encrypted per-customer KMS.
- Ad-hoc forensic exports: Yes — supported via the admin API and Console. Typical delivery SLA: small exports (<=50GB) within 1–2 hours, large exports are chunked and streamed to S3; we provide a signed manifest and MD5/SHA256 checksums.
- Immutability & chain-of-custody: Audit logs are append-only; records include sequence numbers, server timestamps (ISO8601), internal write-hash, and origin tag (route/service id). Deletions are handled via retention policy records and produce an immutable deletion-event audit entry.
- Compliance evidence: Attached SOC2 summary, logging technical spec, and an export runbook (sample schema included).

Answers to your security follow-ups:

1) Programmatic, on-demand exports: Yes. Customers can create scoped API clients (OIDC or API key) with RBAC that allow the SIEM to request exports. Exports can be configured to deliver to a pre-authorized S3 bucket or to a pre-signed URL. We provide signed manifests and per-chunk checksums.

2) Extended retention for hosted customers: We support managed archival exports for customers needing >365 days. Typical pattern: 90-day hot retention in-hosted, then automated monthly archival exports to customer S3 (NDJSON/Parquet) for long-term storage. We can run a searchable archive product for up to 24 months as a managed service under an addendum. For Dedicated and Private deployments, retention is configurable per contract.

3) Large export handling: Exports are chunked (default 1GB chunks), compressed with gzip or brotli, and delivered as multipart uploads to S3. Single-object limits match customer bucket limits; we recommend multipart so large exports stream reliably. Delivery timelines depend on size and network — we provide progress hooks and optional push notifications when the manifest is ready.

4) Audit fields: Every audit-log entry includes tenant_id, request_id, server_timestamp (ISO8601), event_type, service_id, and sequence_number. The internal write-hash and optional signature are included for clients who require chain-of-custody verification.

Evidence: SOC2 control descriptions and attestation are in the attached soc2-summary-redwood.pdf and the Drive folder above. For full artefacts we can provide an NDA-protected package or a remote read-only pod for your auditors (let Neha know the preferred route).
